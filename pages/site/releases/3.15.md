## Release highlights

### Enhanced AI Review metadata Integration & Review Agent Support

Introduced a major revamp to the first-class support for AI-driven code
review workflows. Human comments and AI-generated feedback can now be
clearly distinguished thanks to the new native `isAi` boolean field in
NoteDb.

The Gerrit UI leverages this by rendering a distinctive "sparkle" icon
next to AI-generated comments and check results. To streamline feedback
loops on automated reviews, change owners are now presented with a quick
"Disagree" action button on standalone AI comments.

To support the growing ecosystem of AI plugins, the UI introduces a new
dedicated plugin endpoint (`chat-panel`) in the AI chat view sidebar,
alongside a new `change-view-commit-aside` endpoint for displaying
high-level AI rationales.

Security around these automated agents has also been tightened: the
`aiReview` permission has been transitioned to a standard default-deny
ACL model, ensuring tighter administrative control over which projects and
branches are exposed to AI review agents.

A new feature flag (`GerritBackendFeature__allow_ai_review_for_registered_users`)
allows the preservation of the previous, more permissive permission system
for AI interaction that allows any registered user to access the AI button
and chat regardless of the explicit `AI Review` permission.

### Java 25

Gerrit is now built and tested with JDK 25 by default, producing Java 25
bytecode (major version 69).

The optional `java21` Bazel configuration is still available to build and
release Gerrit for Java 21 (`bazel build --config=java21 release`).

### Bazel modules

The migration of Gerrit's build to [Bazel modules](https://bazel.build/external/migration)
(Bzlmod), started in Gerrit 3.14, is now complete: the legacy `WORKSPACE`-based
dependency mechanism, including `external_plugin_deps.bzl` and the `maven_jar`
rule, has been removed, the web UI build has also moved to Bazel modules, and
Gerrit is built with Bazel 9, where Bazel modules are the only supported
dependency model.

**All plugins must move to Bazel modules.** Plugins that still declare their
external dependencies in `external_plugin_deps.bzl` no longer build and must
declare them in their own `MODULE.bazel` with `rules_jvm_external`, as described
in [Plugins with external dependencies](https://gerrit-documentation.storage.googleapis.com/Documentation/3.15.0/dev-build-plugins.html#_plugins_with_external_dependencies).

### Stack Diff

An experimental _Stack Diff_ dialog, opened from the Relation Chain section, shows
the cumulative file list and diff of a whole relation chain against its base
parent commit, so the combined changes of a stack can be viewed in one place, similar
to PRs.
Enable it with the `UiFeature__stack_diff` experiment.

### Submit Requirement Templates

Administrators can now define reusable submit requirement templates in
[`[submit-requirement-template "<name>"]`](https://gerrit-documentation.storage.googleapis.com/Documentation/3.15.0/config-submit-requirements.html#submit-requirement-template-subsection)
sections of `project.config`, which project owners can pick from in the UI when
creating submit requirements.

Templates are inherited from parent projects and exposed through the new
[`GET /projects/{project}/submit_requirements_templates`](https://gerrit-documentation.storage.googleapis.com/Documentation/3.15.0/rest-api-projects.html#get-submit-requirement-templates)
and
[`GET /projects/{project}/submit_requirements_templates/{name}`](https://gerrit-documentation.storage.googleapis.com/Documentation/3.15.0/rest-api-projects.html#get-submit-requirement-template)
REST endpoints.

### Rich Markdown Diff

A rich rendered view for the diff of Markdown files has been introduced, which
can be toggled from the diff view and the file list, with inline word and block
highlighting.

Comments can be added directly in the rendered Markdown view, including with
the `C` shortcut and on a text selection.

### Searching Changes

New search operators have been added to the change index:

* `onlypaths:` finds changes touching exactly the given set of files,
  allowing submit requirements to replace Prolog rules based on the
  exact list of modified files. Magic files such as `/COMMIT_MSG` are ignored, and
  a single regular expression starting with `^` can be used instead of a
  comma-separated list of paths.

  > **NOTE**: Using the operator with a very commonly changed file may produce a
  > large intermediate result set and be expensive.

* `filecount:` finds changes whose latest patch set touches a given number of
  files, e.g. `filecount:>2`.

* `unmet_requirement:'NAME'` and `unsatisfied_requirement_count:'RELATION''NUMBER'`
  find changes by their unmet submit requirements. These operators are not
  allowed inside submit requirement expressions.

* `has:hashtag` matches changes that carry at least one hashtag.

### Committing Files to a Branch via REST API

The new `POST /projects/{project-name}/branches/{branch-id}/commit` REST
endpoint creates, updates, deletes or renames files on a branch in a single
commit, without cloning the repository or creating a change.

The caller needs Push access on the branch; commit and ref-update validators
(including plugin validators) run, but push-only receive-pack checks are not
applied and matching open changes are not auto-closed.

An optional `base_revision` rejects the request with `409 Conflict` if the
branch has moved, and a request that would not change the tree is rejected with
`400 Bad Request`.

### OAuth Tokens Lifecycle

For sites using OAuth authentication (`auth.type = OAUTH`), OAuth token handling
now covers the whole token lifecycle. The `OAuthServiceProvider` extension point
supports OAuth 2.0 with PKCE (Proof Key for Code Exchange) and can refresh and
revoke tokens, with a new `OAuthTokenRevokedListener` extension point notified
on revocation; existing providers remain compatible. Expired access tokens are
renewed from their refresh token when the provider supports it, including when
[retrieved through the REST API](https://gerrit-documentation.storage.googleapis.com/Documentation/3.15.0/rest-api-accounts.html#get-oauth-token), and a
failed refresh is retried after [`auth.oauthTokenRefreshInterval`](https://gerrit-documentation.storage.googleapis.com/Documentation/3.15.0/config-gerrit.html#auth.oauthTokenRefreshInterval).
Tokens stored in the [`oauth_tokens` cache](https://gerrit-documentation.storage.googleapis.com/Documentation/3.15.0/config-gerrit.html#cache.oauth_tokens)
are encrypted at rest with AES-256-GCM using
[`auth.tokenEncryptionKey`](https://gerrit-documentation.storage.googleapis.com/Documentation/3.15.0/config-gerrit.html#auth.tokenEncryptionKey),
which `init` generates automatically. PKCE, token refresh and token revocation
take effect only when the OAuth provider plugin implements the new extension
point methods; the [oauth plugin](https://gerrit.googlesource.com/plugins/oauth)
supports all of them.

### Administration & Configuration

* **Stale change index recovery**

  Gerrit can now automatically recover change index updates that were lost when
  the process crashed or was interrupted between the NoteDb write and the index
  write. Enable it with `index.staleChangeRecovery = true` (default `false`):
  Gerrit writes per-change intent files under `$site_path/data/pending-index/`,
  recovers leftovers from a crashed process at startup and runs a background
  scanner every `index.staleChangeRecoveryInterval` (default `5m`).

  > **NOTE**: Recovery is only effective when `index.commitWithin` is set to zero
  > and `index.indexChangesAsync` is false.

### High-Availability Configuration

  The new `index.directory` setting configures where Gerrit stores its index
  independently of the site path (default `$site_path/index`; relative paths are
  resolved against `$site_path`).

## Important Notes

### Schema and index changes

Gerrit schema version is updated to `187`.

The Changes index has been upgraded from `v88` to `v90`.

### Offline upgrade

- Stop Gerrit
- Download the new `gerrit.war` and move it to `$GERRIT_SITE/bin`
- Extract all the plugins from `gerrit.war` and move the ones needed into `$GERRIT_SITE/plugins`
- Run the full reindex:
  `java -jar $GERRIT_SITE/bin/gerrit.war reindex --index changes -d $GERRIT_SITE`
- Start Gerrit

### Online upgrade with zero-downtime

Gerrit v3.15.x supports zero-downtime upgrade from Gerrit v3.13 when configured
using a
[high-availability](https://gerrit.googlesource.com/plugins/high-availability/+/refs/heads/master/README.md)
setup.

During the zero-downtime upgrade, Gerrit end-users will not experience any
outage or service disruption and will be able to perform any read/write Gerrit
operation seamlessly.

The zero-downtime upgrade process for high-availability setups
consists of the following steps ([demo](https://youtu.be/vK5qsb0W7q4)):

1. Have Gerrit servers running v3.13 in high-availability
   configuration, healthy and able to handle the incoming traffic properly.
2. Set one of the Gerrit servers to unhealthy.
3. Shutdown the Gerrit server, update gerrit.war, plugins and libs to v3.15.x and start Gerrit again.
4. Verify that the Gerrit server is working properly (e.g. run automated smoke
   tests) and then make it healthy again.
5. Ensure the Gerrit server is fully caught up with the events that happened while
   it was down before directing traffic to it.
6. Repeat steps 2 to 6 for each of the remaining Gerrit servers.

### Known issues

* [Issue 309098227](https://issues.gerritcodereview.com/issues/309098227) [Change 360646](https://gerrit-review.googlesource.com/360646):
The introduction of a per-request ref cache for better performance may break
the repository consistency

  The addition of a new `core.usePerRequestRefCache` setting, true by
  default, introduced a per request (currently per request thread) ref
  cache, helping reduce the overhead of checking if the packed-refs file
  was outdated. However, in some scenarios, such as multi-site or
  concurrency between `git-receive-pack` and `git-gc`, it may lead to
  split-brain inconsistencies and, in the worst-case scenario, to the
  corruption of the underlying repository.

* [Issue 380898784](https://issues.gerritcodereview.com/issues/380898784):
The new `changes_by_project` cache will make the `git-upload-pack` fail intermittently
on projects containing one or more inconsistent changes.

  The introduction of the `changes_by_project` cache is incompatible with projects
  having one or more inconsistent changes, like changes with /meta refs coming from
  unexpected Gerrit serverId.
  The cache makes the `git-upload-pack` fail intermittently
  with internal server errors when it fails to load the change meta-data depending
  on the status of the cache.
  As a workaround, disable the `changes_by_project` cache as follows in `gerrit.config`:
  ```
  [cache "changes_by_project"]
        memoryLimit = 0
  ```

## Performance Changes

* [Change 573862](https://gerrit-review.googlesource.com/c/gerrit/+/573862),
  [Change 573902](https://gerrit-review.googlesource.com/c/gerrit/+/573902),
  [Change 573961](https://gerrit-review.googlesource.com/c/gerrit/+/573961),
  [Change 573981](https://gerrit-review.googlesource.com/c/gerrit/+/573981),
  [Change 633783](https://gerrit-review.googlesource.com/c/gerrit/+/633783):
  The web UI no longer requests expensive diff statistics when loading all
  revisions for the patchset picker, polling for change updates, listing
  cherry-picks and in several change-list queries, using the `SKIP_DIFFSTAT`
  option, which the server now also honors for revision file lists with
  `ALL_REVISIONS` and `ALL_FILES`.

* [Change 573861](https://gerrit-review.googlesource.com/c/gerrit/+/573861):
  High-priority UI requests, such as sending a review, now bypass the frontend
  write-request scheduler queue to reduce UI latency under congestion.

* [Change 573881](https://gerrit-review.googlesource.com/c/gerrit/+/573881):
  Format ChangeInfo results and load change data in parallel in a thread-safe
  way, significantly speeding up REST queries returning many changes.

* [Change 593661](https://gerrit-review.googlesource.com/c/gerrit/+/593661):
  The AI prompt dialog now loads and processes the change's patch content only
  when it is opened, avoiding a browser freeze on page load for very large
  changes when AI review is enabled.

* [Change 598361](https://gerrit-review.googlesource.com/c/gerrit/+/598361):
  Creating and updating draft comments reuses the already loaded change notes
  instead of reopening the repository and resolving the change meta ref again.

* [Change 600221](https://gerrit-review.googlesource.com/c/gerrit/+/600221):
  Speed up expanded-file lookups in the change file list by tracking expanded
  files as a set of paths, which helps changes with many files.

* [Change 609041](https://gerrit-review.googlesource.com/c/gerrit/+/609041):
  SSH change queries now stop processing results promptly when the client
  disconnects, instead of continuing to build output that will never be sent.

* [Change 591501](https://gerrit-review.googlesource.com/c/gerrit/+/591501):
  Speed up building H2 persistent cache bloom filters at startup by reading the
  H2 file up front to warm the OS page cache.

  On a production instance with ~84M disk cache entries this reduced loading
  time from ~22 to ~16 minutes.

* [Change 607281](https://gerrit-review.googlesource.com/c/gerrit/+/607281):
  Warm the OS page cache before collecting disk stats of H2 persistent caches,
  reducing cold-read latency for large caches.

* [Change 601281](https://gerrit-review.googlesource.com/c/gerrit/+/601281):
  Patch set events now compute insertions and deletions from the `diff_summary`
  cache instead of loading full file diffs.

  As a result, the `COMMIT_MSG` and `PATCHSET_LEVEL` files are no longer counted
  in the reported size, restoring the originally intended behavior.

* [Change 619761](https://gerrit-review.googlesource.com/c/gerrit/+/619761):
  Avoid re-evaluating submit rules on open changes when both strict and lenient
  submit records are requested, reusing the records cached on the change data.

* [Change 619706](https://gerrit-review.googlesource.com/c/gerrit/+/619706):
  Reduce NoteDb access when loading change data by keeping patch sets loaded
  from the index, caching the resolved meta revision and no longer loading all
  patch sets to compute `reviewedBy`.

* [Change 619705](https://gerrit-review.googlesource.com/c/gerrit/+/619705):
  Speed up the "Submitted Together" computation by returning immediately for
  standalone changes, without evaluating submit rules, and by removing the
  sequential pre-computation of submit records for multi-change sets.

* [Change 619704](https://gerrit-review.googlesource.com/c/gerrit/+/619704):
  Speed up NoteDb change notes parsing by matching commit footers without
  allocations and streamlining the parser, with a measured ~9-10% latency
  reduction and lower heap churn.

* [Change 619707](https://gerrit-review.googlesource.com/c/gerrit/+/619707):
  Comment listing and formatting is faster thanks to fewer redundant
  comment-context key computations and allocations, with benchmarks on 5,000
  comments showing up to 1.9x faster formatting.

* [Change 623341](https://gerrit-review.googlesource.com/c/gerrit/+/623341):
  Change queries no longer issue a redundant secondary index query when all
  results on the first page are visible and already fill the requested limit,
  halving the backend index queries in that case.

* [Change 619762](https://gerrit-review.googlesource.com/c/gerrit/+/619762):
  Group lookups are faster thanks to batched group index queries by UUIDs and
  members, partitioning bounded by `index.maxTerms`, and cross-population of the
  group cache by ID and name when loading groups by UUID.

* [Change 626801](https://gerrit-review.googlesource.com/c/gerrit/+/626801):
  Git pushes by non-service users now benefit from asynchronous change indexing
  when `index.indexChangesAsync` is enabled, as the push access path is now
  preserved when materializing the user.

* [Change 633782](https://gerrit-review.googlesource.com/c/gerrit/+/633782):
  Avoid reopening the Git repository and recreating readers twice per revision
  when listing modified files against a parent, by reusing the already open
  RevWalk.

* [Change 633784](https://gerrit-review.googlesource.com/c/gerrit/+/633784):
  Keep a user's computed group membership cached across all labels when
  computing permitted labels for change details, instead of recomputing it for
  every label and reviewer.

* [Change 633785](https://gerrit-review.googlesource.com/c/gerrit/+/633785):
  Remove a quadratic scan over patch sets when computing the change kind for
  `ALL_REVISIONS` requests, and open the repository once and share it across all
  revisions.

* [Change 633786](https://gerrit-review.googlesource.com/c/gerrit/+/633786):
  Defer the submission index query used to compute the revert-submission action
  until project state and the `CREATE_CHANGE`/`REVERT` permissions have been
  checked, and fetch only matching change IDs.

* [Change 639863](https://gerrit-review.googlesource.com/c/gerrit/+/639863):
  Speed up base64 encoding of binary REST responses, such as patch and file
  content downloads: for a 3.7 GB patch, encoding now takes ~23s instead of
  ~184s and allocates ~15 GB instead of ~395 GB.

* [Change 639896](https://gerrit-review.googlesource.com/c/gerrit/+/639896):
  The accounts cache reuses a shared All-Users repository handle for lookups
  and cache loads instead of opening the repository each time, reducing
  overhead on the hot path of Git and REST requests, especially when
  `core.useFileKeyByProjectCache = false`.

* [Change 611161](https://gerrit-review.googlesource.com/c/gerrit/+/611161):
  Checks are no longer fetched twice from providers when the selected patchset
  is the latest one.

* [Change 631401](https://gerrit-review.googlesource.com/c/gerrit/+/631401),
  [Change 631841](https://gerrit-review.googlesource.com/c/gerrit/+/631841):
  Speed up the `AllRequestFilter` pipeline, which no longer scans all the
  registered filters on every request or initialisation.

  Distinct filters that are equal according to `equals()`/`hashCode()` can no
  longer both be initialised and used at the same time.

* [Change 631801](https://gerrit-review.googlesource.com/c/gerrit/+/631801):
  `DynamicSet.contains()` is deprecated for removal, with a warning that its
  execution is inherently slow, as it scans all registered items.

* [Change 630261](https://gerrit-review.googlesource.com/c/gerrit/+/630261):
  Commit validation on push no longer performs rename detection when counting
  changed files, making `change.maxFiles` validation about 4x faster for
  commits with many files.

  A renamed file now counts as two changed files (one deletion and one
  addition) against `change.maxFiles`. This can change whether a push is
  accepted or rejected: a change with renames that was within the limit before
  may now exceed it.

* [Change 638024](https://gerrit-review.googlesource.com/c/gerrit/+/638024):
  Gerrit site init now enables compact object headers (JEP 519) by default to
  reduce heap usage.

  Init adds `-XX:+UseCompactObjectHeaders` to `container.javaOptions` in
  `gerrit.config`, also on existing sites, unless the option is already
  explicitly enabled or disabled.

  To opt out persistently, set `-XX:-UseCompactObjectHeaders`, as simply
  removing the option causes the next init on JDK 25 to add it back.

## Permissions & Security Changes

* [Change 599041](https://gerrit-review.googlesource.com/c/gerrit/+/599041),
  [Change 609682](https://gerrit-review.googlesource.com/c/gerrit/+/609682):
  The account query REST API now enforces account visibility: it no longer
  returns accounts that the caller cannot see when `o=DETAILS` is used or for
  suggest queries and, when `accounts.visibility` is restricted (`SAME_GROUP`,
  `VISIBLE_GROUP` or `NONE`), no longer exposes detailed account information
  (`o=DETAILS` and suggest) to unauthenticated callers.

* [Issue 561066231](https://issues.gerritcodereview.com/issues/561066231):
  Setting `cache.oauth_tokens.memoryLimit = 0` now fully disables OAuth token
  storage, so tokens are no longer written to the persistent H2 cache even when
  `diskLimit` is positive.

  When token storage is disabled, `GET /accounts/{id}/oauthtoken` returns `409
  Conflict`. To keep tokens in memory only, set `cache.oauth_tokens.diskLimit =
  0`; if tokens were previously written to disk, stop Gerrit and remove the
  existing `oauth_tokens` persistent cache files.

* [Change 633202](https://gerrit-review.googlesource.com/c/gerrit/+/633202):
  Change notification emails now show the sender's email address alongside the
  display name in action sentences, so a generic or deceptive display name can
  no longer make actions appear to come from someone else.

  The `fromName` variable of change email templates now has the form
  `Name <email>`.

* [Issue 565075161](https://issues.gerritcodereview.com/issues/565075161):
  Replace all uses of the legacy `SHA1PRNG` random generator with the platform
  default `SecureRandom` for OAuth state, signed-push seed, auth-token and
  Change-Id generation, and salt generated group UUIDs and patch-set approval
  UUIDs with cryptographically strong random bytes instead of `Math.random()`;
  the new `SecureRandomUtil` is exported in the plugin API
  (`com.google.gerrit.util.crypto`) so plugins can use it directly.

* [Change 602243](https://gerrit-review.googlesource.com/c/gerrit/+/602243):
  Update `mina-core` from 2.2.4 to 2.2.9 to pick up the fix for
  [CVE-2026-42778](https://nvd.nist.gov/vuln/detail/CVE-2026-42778) (unsafe
  deserialization in `IoBuffer.getObject()`); Gerrit is only affected when
  `sshd.backend = MINA`.

## New Features

* [Change 609281](https://gerrit-review.googlesource.com/c/gerrit/+/609281):
  The H2-based `accountPatchReviewDb` can now be shared safely by multiple
  Gerrit primaries on a shared filesystem (e.g. NFS) without an external
  database. Set `accountPatchReviewDb.h2LockType = jgit` to replace H2's built-in
  file locking with JGit-style `.lock` files; `accountPatchReviewDb.h2LockTimeout`
  (default `30 seconds`) controls how long to retry acquiring the lock.

* [Change 628504](https://gerrit-review.googlesource.com/c/gerrit/+/628504):
  The Lucene index lock implementation is now configurable with
  `index.lockFactory`, which accepts `NATIVE` (default) or `SIMPLE`, recommended
  for filesystems with unreliable OS-level locking such as NFS.

  > **NOTE**: Before changing it, stop all processes writing to the index and
  > delete the leftover `write.lock` files in every index directory, as processes
  > using different lock factories do not lock against each other.

* [Change 561921](https://gerrit-review.googlesource.com/c/gerrit/+/561921),
  [Change 562981](https://gerrit-review.googlesource.com/c/gerrit/+/562981):
  Add a configurable timeout for submit requirement evaluation so that slow or
  expensive expressions cannot block access to a change.

  The new `submitRequirement.executionTimeout` option (default 0, no timeout)
  applies per submit requirement to the combined evaluation of `applicableIf`,
  `submittableIf` and `overrideIf`; when exceeded the evaluation is aborted, the
  expression result gets the new `TIMEOUT` status and the change cannot be
  submitted. Evaluation runs on a dedicated executor sized by the new
  `submitRequirement.evaluationThreads` option (default -1, evaluation in the
  request thread, in which case the timeout does not apply; 0 uses the number of
  available CPUs).

  REST API clients that inspect `submit_requirements.status` should handle the
  new `TIMEOUT` value, reported instead of `UNSATISFIED`; the UI recognizes it.

* [Change 565901](https://gerrit-review.googlesource.com/c/gerrit/+/565901):
  The "Fit to screen" diff preference now offers a "Shrink only" option, giving
  more control over how diffs adapt to the screen size.

  The diff preferences REST API exposes it as the new `responsive_mode` field
  (`NONE`, `SHRINK_ONLY` or `FULL_RESPONSIVE`); `line_wrapping` is deprecated and
  existing line wrapping settings are mapped to `FULL_RESPONSIVE`.

* [Change 572402](https://gerrit-review.googlesource.com/c/gerrit/+/572402):
  Add a "Shown Labels" user preference in the Change Table Columns settings to
  choose, as a comma-separated list of full or abbreviated label names, which
  label columns are displayed in the change list.

  Leaving the field empty keeps showing all labels, as before.

* [Change 607221](https://gerrit-review.googlesource.com/c/gerrit/+/607221):
  Add `caches/memory_request_count` and `caches/disk_request_count` metrics
  exposing the total number of lookups per cache, helping administrators decide
  which caches are worth growing.

* [Change 601041](https://gerrit-review.googlesource.com/c/gerrit/+/601041):
  The `show-caches` SSH command has a new `--cache <NAME>` option that restricts
  the statistics to the named caches, avoiding collecting them for every cache
  on busy servers; it can be repeated to report on several caches.

* [Change 599781](https://gerrit-review.googlesource.com/c/gerrit/+/599781):
  Diffs now respect `.gitattributes` overrides: files marked `-diff` or with the
  `binary` macro are shown as binary instead of as textual diffs, matching Git
  behavior.

* [Change 621901](https://gerrit-review.googlesource.com/c/gerrit/+/621901):
  Add a `histogram` action to `gerrit.sh` that captures a class histogram of the
  live objects on the Java heap with `jcmd`, saving it under
  `$GERRIT_SITE/logs/histogram`, to help investigate memory growth.

* [Change 626881](https://gerrit-review.googlesource.com/c/gerrit/+/626881):
  Reviewers and CCs added via push options can now be suffixed with `:silent`
  (e.g. `-o r=<email>:silent`, `-o cc=<email>:silent`) to add them without
  sending them email notifications for that push.

* [Change 614843](https://gerrit-review.googlesource.com/c/gerrit/+/614843):
  Work-in-progress changes created via the REST API (`POST /changes/`) now
  default to notifying only the owner, so project watchers are no longer emailed
  about them unless `notify` is explicitly set.

  The `notify` field of `ChangeInput` no longer defaults to `ALL`; when
  unspecified it defaults to `OWNER` for WIP changes and `ALL` for ready
  changes, matching the behaviour of pushes with `%wip`.

* [Change 629021](https://gerrit-review.googlesource.com/c/gerrit/+/629021):
  Add the `server/project/submit_requirement_evaluator_latency` metric to track
  how long submit requirement evaluation takes.

* [Change 629601](https://gerrit-review.googlesource.com/c/gerrit/+/629601):
  Add a `minimumInitialDelay` schedule setting so periodic background jobs, such
  as cache pruning, do not run immediately after a restart while preserving
  their configured cadence.

  The first run is advanced by whole `interval` periods until the minimum delay
  is met; the default is `0` (no delay). For cache pruning use
  `cachePruning.minimumInitialDelay`, and set `cachePruning.pruneOnStartup =
  false` to avoid all pruning during the delay.

* [Change 631581](https://gerrit-review.googlesource.com/c/gerrit/+/631581):
  Tasks can now be filtered by state with the new `--state`/`-s` option of the
  `show-queue` SSH command and the `state` option of the `/config/server/tasks/`
  REST endpoint, repeatable to match any of several states.

* [Change 584001](https://gerrit-review.googlesource.com/c/gerrit/+/584001),
  [Change 642014](https://gerrit-review.googlesource.com/c/gerrit/+/642014),
  [Change 642015](https://gerrit-review.googlesource.com/c/gerrit/+/642015),
  [Change 642017](https://gerrit-review.googlesource.com/c/gerrit/+/642017):
  Auth token expiry notifications are now configurable and are also sent once
  a token has expired.

  `auth.token-expiry.notifyDaysBefore` sets the days before expiration on which
  users are notified (default 0, 7, 14 and 21 days), and setting
  `auth.token-expiry.notify = false` disables the notifications. The emails are
  sent asynchronously through the email queue, and a failure to send one
  doesn't stop the remaining ones from being sent.

* [Change 581341](https://gerrit-review.googlesource.com/c/gerrit/+/581341):
  New `check-result-feedback` plugin endpoint in the expanded details of a check
  result wraps the default "Was this helpful?" feedback controls, letting
  plugins customize or replace them; the `CheckResult` is passed as a parameter.

* [Change 572383](https://gerrit-review.googlesource.com/c/gerrit/+/572383),
  [Change 572407](https://gerrit-review.googlesource.com/c/gerrit/+/572407):
  Extend the Flows plugin API so `FlowsProvider` implementations can return
  disabled custom conditions and actions via the optional
  `getDisabledConditions()` and `getDisabledActions()` methods; flow actions
  marked as disabled are hidden from the create-flow dialog.

* [Change 596901](https://gerrit-review.googlesource.com/c/gerrit/+/596901):
  Add `addDiffLayer()` to the annotation plugin API, allowing UI plugins to
  register custom diff layers that are applied when rendering diffs, including
  for LOST lines.

* [Change 629941](https://gerrit-review.googlesource.com/c/gerrit/+/629941):
  New `StopPluginListener.beforeStopPlugin()` method is called just before a
  plugin is unloaded, while its Guice environment and resources are still
  accessible, so listeners can inspect the plugin and clean up in an orderly way.

* [Change 566902](https://gerrit-review.googlesource.com/c/gerrit/+/566902):
  `CommitReceivedEvent` now exposes `cherryPickOf`, so `CommitValidationListener`
  plugins can recognise cherry-picked commits and apply cherry-pick-specific
  validation rules.

* [Change 589582](https://gerrit-review.googlesource.com/c/gerrit/+/589582):
  New `chat-panel-splash-extra` plugin endpoint on the splash page of the AI chat
  panel lets plugins add content there.

* [Change 560863](https://gerrit-review.googlesource.com/c/gerrit/+/560863),
  [Change 571903](https://gerrit-review.googlesource.com/c/gerrit/+/571903),
  [Change 572381](https://gerrit-review.googlesource.com/c/gerrit/+/572381):
  New experiment `GerritBackendFeature__timeout_file_diff_computation` enforces
  a timeout on file diff computation; diffs that time out are reported as
  `diffs_too_expensive_to_compute` and the UI shows a warning with a link to
  download the change for local review.

## Bug fixes

* [Change 571922](https://gerrit-review.googlesource.com/c/gerrit/+/571922):
  Fix the AI review prompt dialog so that `$` sequences (e.g. `$&`, `$1`, `$$`)
  in patch or comment text are inserted verbatim instead of being interpreted as
  replacement patterns.

* [Issue 476288039](https://issues.gerritcodereview.com/issues/476288039):
  Fix Gerrit failing to write to the H2 cache and account patch review database
  folders on Windows by resolving their paths with absolute file paths instead
  of URIs.

* [Change 548821](https://gerrit-review.googlesource.com/c/gerrit/+/548821):
  Reverting a change no longer adds deleted accounts as owner, reviewers or CCs
  of the revert change.

* [Issue 507078595](https://issues.gerritcodereview.com/issues/507078595):
  The `config/server/index.changes` REST API with `delete_missing` set to `true`
  now correctly deletes changes missing from NoteDb from the index when they are
  identified in `project~changeNumber` format.

* [Change 592841](https://gerrit-review.googlesource.com/c/gerrit/+/592841):
  The "URL and title" format of the copy-link dialog now separates the URL and
  title with a dash, so pasted links are no longer parsed with a trailing colon
  as part of the URL.

* [Issue 519743027](https://issues.gerritcodereview.com/issues/519743027):
  Fix syntax highlighting of Objective-C++ (`.mm`) files containing C++14 digit
  separators, which previously broke highlighting for the rest of the file.

* [Change 604481](https://gerrit-review.googlesource.com/c/gerrit/+/604481):
  Submit requirements with an invalid regular expression now evaluate to an
  error result instead of causing a 500 error in the REST API.

* [Change 554321](https://gerrit-review.googlesource.com/c/gerrit/+/554321):
  Pushing a new patch set no longer demotes author and committer to CC.

* [Change 642068](https://gerrit-review.googlesource.com/c/gerrit/+/642068):
  The `reviewer.skipAddingAuthorAndCommitterAsReviewers` project option is now
  also honored when pushing new patch sets to an existing change, which no
  longer adds and emails the commit author and committer.

* [Change 611261](https://gerrit-review.googlesource.com/c/gerrit/+/611261):
  The email verification link in the HTML variant of the new email registration
  message is now clickable.

* [Change 621762](https://gerrit-review.googlesource.com/c/gerrit/+/621762):
  Fix the `migrate-labels:review` project REST endpoint adding extra escape
  characters to the `applicableIf` expression of generated submit requirements.

* [Change 612843](https://gerrit-review.googlesource.com/c/gerrit/+/612843):
  The `commit-msg` hook no longer appends a duplicate Change-Id when the commit
  message contains `KEY=value` style footers such as `TAG=...`.

* [Change 617181](https://gerrit-review.googlesource.com/c/gerrit/+/617181):
  Queued tasks that are not associated with a project, such as most SSH
  commands, can now be retrieved and killed via `kill` and `GET`/`DELETE
  /config/server/tasks/{task-id}` by users with View Queue, instead of failing
  with "No such task" / 404.

* [Change 622881](https://gerrit-review.googlesource.com/c/gerrit/+/622881):
  Stop logging a spurious SEVERE "Internal server error" when an SSH client
  disconnects while its command is blocked in a library call, such as a Lucene
  index query; these disconnections are now logged at debug level.

* [Change 619709](https://gerrit-review.googlesource.com/c/gerrit/+/619709):
  Internal change lookups by project commits or legacy change IDs no longer fail
  when the number of terms exceeds `index.maxTerms`; they are now split into
  batched sub-queries and the results are de-duplicated.

* [Change 623361](https://gerrit-review.googlesource.com/c/gerrit/+/623361):
  Fix group cache batch eviction by UUID, which previously never invalidated the
  cached entries because the wrong key type was passed.

* [Change 623882](https://gerrit-review.googlesource.com/c/gerrit/+/623882):
  Evaluating a change query expression with `use-index=true` now falls back to
  NoteDb when the change is missing from the index (e.g. due to replication lag)
  instead of failing with HTTP 500.

* [Change 625141](https://gerrit-review.googlesource.com/c/gerrit/+/625141):
  Suggested edit previews now diff the original and fixed text with
  HistogramDiff, so unchanged lines inside the replaced range are shown as
  common lines instead of being deleted and re-added.

* [Change 628321](https://gerrit-review.googlesource.com/c/gerrit/+/628321):
  Canceling queued tasks that have not started yet now invokes their cancel
  handler, so SSH fetches no longer hang forever and HTTP requests receive a 503
  instead of stalling until `httpd.maxwait`.

* [Change 633481](https://gerrit-review.googlesource.com/c/gerrit/+/633481):
  Incoming email parsing no longer fails with a NullPointerException on text or
  HTML parts that declare no charset.

* [Issue 564637471](https://issues.gerritcodereview.com/issues/564637471):
  With `index.autoReindexIfStale = true`, Gerrit now correctly detects a change
  duplicated in both the Lucene `open` and `closed` sub-indexes and reindexes it
  from NoteDb, removing the stale copy.

  This fixes detection and repair of existing duplicates; it does not address
  the concurrent-write race that can create them.

* [Change 634174](https://gerrit-review.googlesource.com/c/gerrit/+/634174):
  The change cleanup runner and the `POST /config/server/cleanup.changes` REST
  endpoint are now bound only on primary servers and are no longer available on
  replicas.

* [Change 634363](https://gerrit-review.googlesource.com/c/gerrit/+/634363):
  Fix Jetty rejecting URIs containing an encoded backslash (`%5C`), e.g.
  reopening a copied change-query URL such as `branch:^a\.b`, by allowing
  `SUSPICIOUS_PATH_CHARACTERS` in URI compliance.

* [Change 635866](https://gerrit-review.googlesource.com/c/gerrit/+/635866),
  [Change 635867](https://gerrit-review.googlesource.com/c/gerrit/+/635867):
  Fix updating draft comments: a draft updated without a path keeps its
  existing path and, unless given, its line, range and side instead of failing
  with HTTP 500, and a draft updated without the `unresolved` field keeps its
  unresolved state, also for ported comments.

* [Change 635324](https://gerrit-review.googlesource.com/c/gerrit/+/635324):
  Comment replies posted via the REST API with `in_reply_to` set and line, range
  or side omitted now inherit them from the parent comment, instead of being
  stored as file-level comments that split from their thread in the UI.

* [Change 635088](https://gerrit-review.googlesource.com/c/gerrit/+/635088):
  Stopping Gerrit after unloading a plugin no longer waits for the plugin
  cleaner's one-minute delay; the scheduled cleaner is cancelled on shutdown.

* [Change 620681](https://gerrit-review.googlesource.com/c/gerrit/+/620681),
  [Change 620701](https://gerrit-review.googlesource.com/c/gerrit/+/620701):
  `StartPluginListener`, `StopPluginListener` and `ReloadPluginListener`
  implementations provided by plugins are now honored, so plugins can listen
  to the loading, unloading and reloading of other plugins.
